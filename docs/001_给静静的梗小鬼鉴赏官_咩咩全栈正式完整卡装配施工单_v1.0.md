# 5. Page 01｜今日鉴赏：老虎机

这是本卡 MVU 最重要的特色模块。

## 5.1 数据池

唯一正式种子池：

`mvu/src/pools/slot-pools.v0.1.json`

现有：

- 外貌种子：72 条；
- 等效点赞：7 档；
- 梗词条：226 条；
- 基础组合：113,904 种。

不得擅自把种子池改成“预制完整梗小鬼角色池”。

## 5.2 三个滚轮

老虎机只抽：

1. 外貌特征；
2. 等效点赞等级；
3. 梗。

滚轮停止后只输出三项种子结果。

完整梗小鬼仍由正文 AI 根据 `BLUE12｜随机梗小鬼生成规则` 结合当前场景生成：

- 姓名；
- 人格；
- 梗核；
- 说话方式；
- 异常表现；
- 能力；
- 行为模式；
- 热度趋势；
- 当前地点关系。

MVU不得自己预制完整角色正文。

## 5.3 每日一次机制：直接复用成熟实现

每日抽取技术已经成熟。

**不要重新设计一套“每日系统”。**

直接复用咩咩全栈 / 既有成熟项目中已经验证过的：

- 同一自然日仅一次；
- 当天结果锁定；
- 刷新 / 重开 MVU 不重抽；
- 跨自然日自动重置；
- 新一天允许再次抽取。

禁止提供免费重抽、确认后重抽、刷新重抽。

## 5.4 点赞池

正式七档：

百赞级 → 千赞级 → 万赞级 → 十万赞级 → 百万赞级 → 千万赞级 → 全网级。

抽取权重以 `slot-pools.v0.1.json` 为唯一数据源。

点赞档位只代表传播规模，不代表战力、危险、恶意、稀有度或Boss等级。

UI不得写成 SSR / UR 稀有度。

## 5.5 动画

需要有真实老虎机滚动观感，但优先保证 Android / SillyTavern 流畅。

不需要重型粒子、WebGL或复杂物理。

建议停止顺序：

外貌 → 等效点赞 → 梗。

梗作为最后结果，停顿反馈最明显。

# 6. Page 02｜栖江线路：地铁线路图视觉

不做3D。

不做真实地图SDK。

不做复杂坐标系统。

使用轻量 SVG / DOM / CSS 制作**地铁线路图式城市导航**。

线路对应：

- 南城线 → 南城老城区；
- 北岸线 → 北岸新城区；
- 学城线 → 东部大学城；
- 工业线 → 西部老工业带；
- 山麓线 → 西北山麓—水库带；
- 沿江线 → 沿江中央带；
- 东南支线 → 东南近郊—乡镇农业带。

42个固定核心地点映射为站点。

点击站点：

显示地点名 + 一句简介 + `前往`。

点击 `前往` 的职责仅为：

**通过咩咩全栈现有输入桥 / 填字桥，将“{{user}}决定前往某地点”的玩家意图送入输入框或标准交互链。**

地图不得：

- 自己推进时间；

- 自己判定到达；
- 自己触发固定真祟；
- 自己生成剧情结果。

正文 AI 继续负责发生什么。

如果咩咩已有当前位置变量，则只读 / 复用；不要建立第二套位置状态。

# 7. Page 03｜异模办：16人好感度与秘密

固定显示：

- 10名固定鉴赏官；
- 6名固定普通工作人员；
- 共16名角色。

## 7.1 好感度：直接读取咩咩预设

这套技术已经成熟。

**禁止再造第二套好感度变量。**

施工时必须先读取最新版咩咩全栈中真实好感度字段与现有读取桥实现，然后直接适配。

正确数据流：

咩咩预设维护好感度 → MVU只读展示。

错误数据流：

MVU自己维护一份好感度 → 再尝试和咩咩同步。

不得使用错误方案。

## 7.2 显示内容

每个角色卡至少显示：

- 头像；
- 姓名；
- 身份 / 岗位；
- 当前咩咩好感度；
- 好感度条；
- 私人秘密锁定状态。

## 7.3 50点秘密

规则：

- 好感度 < 50：秘密锁定；
- 好感度 ≥ 50：解锁1条个人秘密；
- 一旦解锁，永久保持已解锁，不因后续好感下降重新上锁。

v1.0 每人只需要1条秘密。

秘密可以是：

- 黑历史；
- 隐秘爱好；
- 生活小弱点；
- 收藏；
- 羞耻网名；
- 反差习惯；
- 私人过去片段；
- 很可笑但本人死不承认的事情。

不要16个人全部写成悲惨创伤。

本作需要保留大量逗比、日常和反差。

## 7.4 16名角色头像：本轮由静静直接生成

用户已明确授权：

**本轮不要等待用户逐个提供头像，也不要把头像任务退回给绒绒。**

静静直接根据现有角色条目生成16张统一规格头像，并接入MVU第三页。

要求：

1. 生成前逐一读取对应角色文件；
2. 外貌必须遵守现有发色、发型、瞳色、年龄感、标志物、服装气质与物种特征；
3. 白月绫、陶夭夭等非普通人类角色不得丢失核心非人特征；
4. 不凭感觉改变人物设计；
5. 头像统一画风、统一构图、统一尺寸；
6. 建议头像以头肩 / 半身近景为主，适配小卡片裁切；
7. 生成后做人物对应表和QA，防止串角色；
8. 媒体文件放入本项目正式媒体目录，路径进入manifest / 构建源，不使用临时会话链接作为运行时依赖。

头像生成属于本轮正式施工内容。
